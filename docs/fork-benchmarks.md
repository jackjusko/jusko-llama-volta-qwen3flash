## 2. Qwen3.8-Flash-Next on 2x V100 (this layer's daily driver)

Model: `AD-5.00bpw-Q5_K_M-M64` (110.5 GB; 54.4 GB n-gram table host-only; 51.8 GiB
PLE host-only). Context 163840, `-sm layer`, F16 KV, no speculation, `QWEN4EXP_QSA_SLIM=1`.

### 2.1 The problem the sweep solved

Before any of this layer: short decode ~32 t/s, but long "thinking" decode **flatlined
at 13-14 t/s** at ~20-34 % GPU util. Diagnosis (see `README-FORK.md` B1-B3): the QSA
indexer walked the KV **high-water mark** (`used_max_p1`) and scored all `n_kv` cells
dense in 12 layers. Not bandwidth, not the PLE — a graph that got bigger than the
prompt.

### 2.3 Wave log (condensed)

- **V-wave (41 cells, Volta/NVLink/long-ctx notes on every cell):** `-sm layer` beat
  `-sm tensor` — the tensor-split AllReduce+Meta path was the tax, NVLink idle under
  layer ping-pong; q8 KV (27.3 vs 28.7 @20k) and P2P-off (neutral decode) killed;
  `GGML_CUDA_VOLTA_DECODE_MMA` crashed CUDA init; `_DECODE_VEC` no win; P40
  `--moe-cache auto` (experts un-resident) killed at 5 t/s; `-ncmoe 4/8` killed
  (17/16 t/s); tensor ratios 0.6/0.4 OOM, 0.55/0.45 died mid-PP.
- **C-wave (160k):** ub 768 + pipeline-copies 1 is the only 160k layout that fits;
  OOM abort fast-fails health checks at ~40 s.
- **H-wave (code):** `QWEN4EXP_QSA_LOG` neutral (first graph still builds at
  n_kv=163840; `used_max_p1` drives the runtime slope). SLIM fixed a `buffer` assert
  (skip unused `cell_blk` fill) and promoted 20k/60k/150k (2.2 Stage 3). GATHER
  killed (32.2 @2048). DECODE_VEC+slim killed. POOLED_K: real long-ctx axis (60k
  24.7, 150k 17.6) but -2k tax -> length-gated, off. FUSED_LID 33.5/29.0 -> off,
  kernel kept.
- **L-wave (long ctx):** L00 tile-skip decode win at 60k/150k (see ladder); MMA-skip
  half reverted (PP). L01 GATHER_AUTO killed (22.2 @60k). Metadata from the run:
  `indexer_top_k=2048`, compress 4 every 4th layer (12 QSA / 36 GDN), slim width 2051,
  `n_top_b=513`.
- **Idle-GPU note:** `--pipeline-copies 2` duplicates graph *inputs*; it does **not**
  overlap the two V100s on a single decode token (GPU util 23/30 @TG-2048). Layer-i
  on GPU0 while layer-i+1 on GPU1 needs a scheduler change, not a flag.

## 3. Ruled out (full negative list)

| Lever | Result |
|---|---|
| n-gram speculation (this checkpoint has no MTP tensors) | unique 2k: 28.8 vs 30.0 baseline (loss); 20k: 23.5 (loss); "wins" were clean-slot artifacts |
| `--cache-ram`>0 + slot similarity | poisoned `used_max_p1`; permanent dive 13-14 t/s — always `0` on this arch |
| q8_0 KV | 27.3 vs 28.7 @20k; dequant tax > saved HBM at this occupancy |
| QSA GATHER / GATHER_AUTO | H04: 32.2 @2048; L01: 22.2 @60k |
| QSA POOLED_K default-on | 33.4-33.7 @2048 (tax) despite 60k/150k wins |
| FUSED_LID default-on | 33.5 / 29.0 |
| `VOLTA_DECODE_MMA` | CUDA init crash on this build |
| `VOLTA_DECODE_VEC` | no TG win (H08) |
| `-sm row` / `-fa off` | unsupported / fails to load |
| 160k ctx + ub >= 1024 | OOM (+2.8 / +5.6 GiB compute buffers) |
| smaller weight quant to "fix" long ctx | wrong diagnosis — stall is QSA, not weight BW; Q5_K_M retained |
| `--fit on` | mis-sizes qwen4exp; `--fit off -ngl 99` |
| `--moe-cache auto` (2x V100, experts resident) | nothing to cache; with P40: 5 t/s decode |
| `mmap+mlock` whole GGUF | exceeds 128 GB RAM with VRAM weights; use `LLAMA_MLOCK_PLE=1` (PLE ranges only) |
| `--lazy-mode auto` | PLE fetched on demand from disk: PP ~45 t/s |

## 4. Appendix — same binary, sibling workload (Ling-3.0-flash, 2x V100 + P40)

The `--moe-cache` / MMVQ-cache code (README-FORK B6) was built for this hybrid regime
(~9.4 GiB experts spilled to RAM inside 8 partial layers on 3 cards, bailingmoe3 arch):

- C3-3way-resident (2x V100 + P40, MTP on): 30.6 t/s gen1 / **33.5 t/s gen2** at 8k
  ctx, MTP acceptance 48.6 %.
- Measured deltas: MTP **-28..36 % TG removed** when off; adding the P40 slice
  **-40..50 %** when absent; `--moe-cache auto` slower than fit-2048/cache-off at that
  coverage; `--spec-draft-n-max >= 4` strictly negative (per-position acceptance
  0.908 / 0.456 / 0.155).
- Decode verdict for spilled-MoE: latency/sync-bound (8-10x above the weight-bandwidth
  roofline), expert spill second. Full write-up lives in the sibling project, outside
  this repo.

## 5. Reproducing

1. Read `examples/windows-dual-v100/README.md` (edit four paths at the top of
   `run-env.cmd`).
2. Launch via `run-server.cmd`; `bench-matrix.ps1` drives fixed workloads
   (PP-2k/8k, TG-64-at-{2048,2048..150000}, TG-think-512) and appends one JSONL row
   per run with GPU util samples.
3. Promotion rules used: a config is a **win** only if TG-2048 *and* TG-20k/60k
   improve without collapsing PP-2k; GPU util < 40 % during decode = stall, not a
   flag problem; every A/B kept exact-token checks.
